# Как работать в этом репозитории

## Главное правило: сначала показать, потом main

Оформление не выкатывается раньше, чем его приняли. Так уже три
раза выходило: капсульный редизайн откатывали, стиль Apple
откатывали, винно-красный по референсу — тоже. Цена ошибки — не
потерянный код (он в истории), а потерянное доверие.

Работаем на ветке, показываем снимки, и только после «заливай» это
едет в `main`. Чужие макеты один в один не повторяем: берём
направление (палитру, плотность, ритм), а не чужую работу.

## Что это за сайт

Статический сайт студии: главная плюс три страницы услуг плюс
страницы кейсов. Собирается Vite, рисуется React, оформляется
Tailwind, движется Motion. Публикует Cloudflare из этого
репозитория.

Адрес — `https://vrtll.dev/`, почта — `admin@vrtll.dev`.

### Оформление — «чёрное стекло»

Одна плоскость чёрная. Всё, что над ней, поднято не рамкой, а
светом: полупрозрачный слой плюс волосяная линия по верхней
кромке. Три правила:

1. **Цвет почти не используется.** Кислотный `#d8ff3e` — сигнал, а
   не заливка: квадрат в знаке, точка статуса, одна кнопка, фокус.
   Больше трёх акцентов на экране — значит что-то пошло не так.
2. **Глубина делается прозрачностью, а не тенью.** Заметная тень
   читается как наклейка.
3. **Воздух важнее плотности.**

Светлой темы нет намеренно. Шрифты — `Unbounded` (заголовки) и
`Onest` (текст), оба лежат свои.

Токены объявлены через `@theme` в `app/main.css`, поэтому Tailwind
делает из них утилиты сам: `--color-glass` превращается в
`bg-glass`. Второго списка цветов в конфиге нет — и не заводи.

## Где что лежит

```
app/
  index.html          шаблон: мета, CSP, шрифты
  entry-client.jsx    гидратация в браузере
  entry-server.jsx    отрисовка при сборке
  main.css            токены Tailwind и база
  App.jsx             оболочка: шапка, страница, подвал
  lib/
    content.js        ВСЕ тексты, цены, кейсы, переводы
    routes.js         список страниц: путь, title, description
    i18n.jsx          язык, валюта, курс
    sentry.js         отчёты об ошибках (по желанию)
  components/         секции страницы
  components/ui/      примитивы: Button, Surface, Section, Reveal…
  pages/              Home и ServicePage (три страницы услуг)
worker/index.js       единственная живая ручка: POST /api/lead
scripts/              сборка и проверки
cases/                страницы кейсов, обычный html
fonts/ css/fonts.css  свои шрифты (собирает scripts/fonts.py)
```

**Тексты правятся только в `app/lib/content.js`.** Оттуда они
попадают и на страницы, и в структурированные данные, и в карту
сайта. Второй копии правды нет.

**Страница добавляется только в `app/lib/routes.js`.** Оттуда её
подхватят и сборка, и карта сайта, и проверки.

## Сборка

```
npm run dev      живая перезагрузка на время работы
npm run build    собрать dist/ и прогнать проверки
npm run verify   то же плюс проверки в живом браузере
```

`scripts/build-app.js` делает три шага: собирает приложение для
браузера, потом то же для Node и рисует каждую страницу в готовую
разметку, потом кладёт рядом статику (шрифты, снимки, кейсы,
воркер, заголовки).

**Отрисовка при сборке — не украшение.** Поисковик и человек с
выключенным JS обязаны видеть текст, цены и вопросы сразу.
`check.js` считает символы в разметке каждой страницы и ругается,
если их стало мало.

## Проверки

Всем, кроме `check.js`, нужен `NODE_PATH=/tmp/node_modules`.

- `npm run check` — 17 проверок по собранному `dist`: страницы,
  текст в разметке, переводы, ссылки, форматы снимков, CSP, форма
  и воркер, вес первого экрана, JSON-LD, карта сайта, кеш.
- `npm run smoke` — 27 проверок в живом браузере: страница без JS,
  язык, валюта, раскрытия, форма во всех её исходах, страницы
  услуг, бургер и Escape.
- `npm run perf` — сколько байт и запросов уходит на первом экране
  (текст отдаётся сжатым, как на сервере).
- `npm run look 390 dark 0,1200` — снимки плюс отчёт о том, что
  вылезает за экран. `LOOK_PAGE=boty/index.html` — другая страница.

Прогоняй `npm run verify` после любой правки.

## Заявки с формы

Форму принимает **`worker/index.js`** — единственная живая ручка,
`POST /api/lead`. Он проверяет присланное и пересылает заявку
владельцу в Telegram. Базы нет: заявка живёт в переписке. В логи
воркер не пишет ничего.

В панели Cloudflare (Variables and Secrets **самого воркера**, а
не раздела Build) нужны:

- `TG_BOT_TOKEN` — токен бота, секретом;
- `TG_CHAT_ID` — куда слать.

Проверить можно с телефона: открыть `/api/lead` в браузере. GET
отвечает `{"configured": true}` или `false` и подсказкой. Бот не
может написать первым — после настройки нажми ему `/start`.

Защита от автоматов — поле-ловушка `site` за пределами экрана.
Капчи нет намеренно: она стоит дороже, чем пара спамных заявок.

## Отчёты об ошибках (Sentry)

Подключаются, только если при сборке задана `VITE_SENTRY_DSN`. Нет
переменной — пакет не грузится вовсе, ни одного лишнего килобайта.
Настройки в `app/lib/sentry.js`: чужие ошибки (расширения браузера)
отсеиваются, личные данные не отправляются.

## Что важно помнить

- **CSP строгая, кроме стилей.** `script-src 'self'` — именно он
  защищает от чужого кода. `style-src` пришлось открыть: Motion
  анимирует через атрибут `style`. Скриптам вольности не давать.
- **Снимки кейсов лежат в трёх форматах.** `<picture>` отдаёт
  avif, затем webp, потом jpg. После замены любого `.jpg` надо
  прогнать `npm run images`, иначе браузер тихо съедет на тяжёлый
  jpg. `check.js` за этим следит.
- **Шрифты свои.** `npm run fonts` (нужен fonttools) собирает
  `fonts/` и `css/fonts.css` из копии в `brand/story/fonts`.
  В имени файла хеш содержимого — поэтому вечный кеш честен.
  Поменялись шрифты — поправь адреса в `<link rel="preload">`.
- **«Орбіта» и «Пліткарка» сняты с сайта** по просьбе владельца.
  Записи убраны из `PROJECTS`, папки и снимки не попадают в `dist`
  (`SKIP_CASES` в `scripts/build-app.js`). Не возвращать сами по
  себе.
- **`sw.js`** — служебный воркер: страницы «сеть, потом кеш», всё
  остальное «кеш, потом сеть». Чужие домены не трогает.
- Деньги везде хранятся целыми числами.
- Тексты на сайте украинские, комментарии в коде — русские.
- Ничего не выдумывать: цены, сроки и отзывы берутся из реальных
  данных или не пишутся вовсе.
