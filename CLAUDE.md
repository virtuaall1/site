# Как работать в этом репозитории

## Главное правило: сначала прев'ю, потом main

Оформление живого сайта **не меняется сразу**. Даже когда владелец
говорит «нужен сайт с таким оформлением» — сперва отдельная страница
в `preview/`, скриншоты, выбор. И только после «заливай» это едет в
`main`.

Так уже три раза выходило: капсульный редизайн откатывали, стиль
Apple откатывали, винно-красный по референсу — тоже. Каждый раз
работа была нормальная, но её выкатывали раньше, чем приняли. Цена
ошибки — не потерянный код (он в истории), а потерянное доверие.

Чужие макеты с Pinterest и дрибббла один в один не повторяем: берём
направление (палитру, скругления, плотность), а не чужую работу.

## Что сейчас на сайте

Прежнее оформление: **ink + бумага + кислотный акцент** `#d8ff3e`,
шрифты `Unbounded` и `Onest`, фоновая сетка точек на канвасе,
«расшифровка» заголовков, магнитные кнопки. Всё это живёт в
`css/style.css` и `js/app.js`.

## Временно снятые кейсы

**«Орбіта» и «Пліткарка» убраны с сайта по просьбе владельца.**
Не возвращать сами по себе. Что сделано:

- записи удалены из `PROJECTS` в `js/content.js` (лежат в истории git);
- у услуг `landing` и `webapp` убран `caseLink` — он вёл на эти кейсы;
- папки `cases/orbita`, `cases/plitkarka` и оба снимка не попадают в
  `dist`: список `SKIP` в `scripts/build.js`. Исходники на месте.

Вернуть — убрать пути из `SKIP` и вернуть записи в `PROJECTS`.

## Что лежит рядом и не применено

- **`css/apple-ds.css`** — дизайн-система в эстетике Apple. Скилл с
  токенами, списком классов и чеклистом — в `.claude/skills/apple-ds/`.
  На сайте не используется; годится для прев'ю и новых страниц.
- Варианты редизайна, которые откатили, целиком лежат в истории:
  `git log --oneline` → «Сайт переоформлен на дизайн-систему apple-ds»
  (винно-красный), «Liquid Glass», «Шесть кейсов переведены в стиль
  Apple». Вернуть можно `git revert --no-commit <хеш-отката>`.

## Что сделано для скорости — не ломать

- **Списки едут готовой разметкой.** Кейсы, цены, шаги и вопросы
  вставляет в `index.html` сборка (`scripts/prerender.js`), а не
  только скрипт. Поисковик и человек с выключенным JS видят их
  сразу. `app.js` помечен: контейнер с `data-pre="uk"` он первый
  раз не перерисовывает. Появился новый список с переводами —
  добавь его и туда, `check.js` сверяет число строк с данными.
  Тем, у кого JS выключен, `.reveal` показывает `css/nojs.css`
  через `<noscript>`.
- **Шрифты лежат свои.** `fonts/` и `css/fonts.css` собирает
  `npm run fonts` (`scripts/fonts.py`, нужен fonttools) из копии в
  `brand/story/fonts`. Гугловых доменов на странице нет, CSP
  ужат до `'self'`. В имени файла хеш содержимого — поэтому вечный
  кеш честен; поменялись шрифты — поправь адреса в
  `<link rel="preload">`, `check.js` за этим следит.
- **Языки разъезжаются на сборке.** В `content.js` оба языка лежат
  рядом (так удобно править), но в браузер уезжает только общее и
  украинское. Английский ждёт в `js/lang-en.js` и приезжает, лишь
  когда человек переключил язык. Делит `scripts/lang.js`, обход
  общий — новый список с `en` разделится сам.
- **Снимки кейсов лежат в трёх форматах.** `<picture>` отдаёт avif,
  затем webp, и только потом jpg. Пережимает `python3 scripts/images.py`
  из того же исходника — после замены любого `.jpg` его надо
  прогнать, иначе `<picture>` тихо съедет на тяжёлый jpg. `check.js`
  за этим следит.
- **В GitHub идём не сразу**, а когда человек подобрался к разделу
  портфолио (`whenNear` в `app.js`). Свои работы при этом рисуются
  сразу — они не ждут сети.
- **`sw.js`** — служебный воркер: страницы «сеть, потом кеш», всё
  остальное «кеш, потом сеть». Чужие домены он намеренно не трогает,
  иначе однажды покажет позавчерашний курс как сегодняшний.
- **`_headers`** держит css и js вечно (`immutable`): сборка дописывает
  к ним `?v=`, адрес нового файла всегда другой. Сам воркер — с
  `no-cache`, иначе сайт застрянет на старой версии.

## Заявки с формы

В разделе «Далі» стоит форма: имя, контакт, задача. Её принимает
**`worker/index.js`** — единственная живая ручка на весь сайт,
`POST /api/lead`. Он проверяет присланное и пересылает заявку
владельцу в Telegram. Базы нет: заявка живёт в переписке. В логи
воркер не пишет ничего — там не должно оказаться чужого телефона.

Чтобы форма заработала, в панели Cloudflare (Settings → Variables)
нужны две переменные:

- `TG_BOT_TOKEN` — токен бота, от которого придёт заявка (секрет);
- `TG_CHAT_ID` — куда слать: свой id или id канала.

**Пока их нет, ручка отвечает 503**, и форма показывает запасной
путь: те же кнопки в Telegram и на почту остались прямо под ней.
Поэтому выкатывать форму имеет смысл после того, как переменные
заданы, — иначе посетитель увидит «форма не відповідає».

Проверить, дошли ли переменные до воркера, можно с телефона:
открыть `/api/lead` в браузере. GET отвечает `{"configured": true}`
или `false` и подсказкой — значений при этом не показывает.

Воркер подключён в `wrangler.jsonc` (`main` плюс биндинг `ASSETS`):
статику по-прежнему отдаёт платформа, воркер просыпается только
там, где файла нет. `check.js` сверяет, что адрес ручки в `app.js`
и в воркере — один и тот же.

Защита от автоматов — поле-ловушка `site`, спрятанное за пределы
экрана: человек его не видит и не таббается в него, а заполненное
поле выдаёт бота. Капчи нет намеренно: она стоит дороже, чем
пара спамных заявок в день.

## Что собирается само

- **JSON-LD** (`scripts/seo.js`) — цены, вопросы и работы берутся из
  `content.js` при сборке и подставляются вместо `<!--JSON-LD-->`.
  Второй копии правды нет: поменял цену — поехало и в разметку, и в
  структурированные данные.
- **`sitemap.xml`** пишется по готовому `dist`, а не по списку в
  голове: снятый кейс выпадает из карты сам.
- **`img/og.jpg`** — картинка для соцсетей, `npm run og`.

## Инструменты проверки вёрстки

Всем нужен `NODE_PATH=/tmp/node_modules`, кроме `check.js`.

- `npm run check` — 22 проверки без браузера: переводы, якоря,
  дубли id, ссылки в никуда, вес, форматы снимков, сборка JSON-LD,
  заголовки кеша.
- `npm run html` — сходится ли вложенность тегов.
- `npm run smoke` — 30 проверок в живом браузере: тема, язык,
  валюта, бургер, Escape и возврат фокуса, раскрытия, avif в
  `<picture>`, подсветка раздела, отложенный поход в GitHub.
- `npm run perf` — сколько байт и запросов уходит на первом экране;
  меряет `dist`, с `--src` — исходники. Текст отдаётся сжатым, как
  на сервере, — числа те же, что увидит человек.
- `npm run look 390 dark 0,1200` — снимки страницы плюс отчёт о том,
  что вылезает за экран.
- `npm run verify` — check + html + smoke одной командой.

Прогоняй `npm run verify` после любой правки. Часть проверок
смотрит на `dist` (готовая разметка, свои шрифты, отдельный
английский), поэтому перед `smoke` собирай: `node scripts/build.js`.

## Что важно помнить про проект

- Сайт публикуется **Cloudflare** из этого репозитория, а не GitHub
  Pages. Workflow GitHub Actions удалён намеренно: он слал лишние
  уведомления. Проверки живут в `npm run build`.
- Команда сборки в панели Cloudflare — `npm run build`, каталог —
  `dist` (задан в `wrangler.jsonc`).
- Адрес сайта — `https://vrtll.dev/`, почта — `admin@vrtll.dev`.
  Адрес записан прямо в исходниках (`HOME` в `scripts/build.js`),
  задавать `SITE_URL` при сборке больше не нужно — переменная
  осталась только чтобы перебить адрес для черновой копии.
- Деньги везде хранятся в копейках целыми числами.
- Тексты на сайте украинские, комментарии в коде — русские.
- Ничего не выдумывать: цены, сроки и отзывы берутся из реальных
  данных или не пишутся вовсе.
