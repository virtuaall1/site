# virtuaall — сайт-портфолио и продажа Telegram-ботов

Статический сайт без сборки: открыл `index.html` — и он работает.
Публикуется Cloudflare из этого репозитория при пуше в `main`.

**Живая версия:** https://vrtll.dev/

## Что где лежит

```
index.html          разметка
css/style.css       вся вёрстка и дизайн-система
js/content.js       ← ЦЕНЫ, УСЛУГИ, КОНТАКТЫ, ПЕРЕВОДЫ (правится только это)
js/app.js           логика: язык, GitHub API, анимации, фон
scripts/check.js    проверки перед деплоем
```

## Как поменять цены или услуги

Всё в `js/content.js`, разметку трогать не нужно.

```js
{
  id: 'shop',
  price: '$250+',        // '?' — покажет «цена по задаче»
  featured: true,        // метка «хит»
  uk: { name: '…', desc: '…', bullets: ['…'] },
  en: { name: '…', desc: '…', bullets: ['…'] }
}
```

Контакты — там же, в блоке `LINKS` наверху файла.

## Как добавить свои работы

Секция «Репозитории» тянет данные с GitHub сама, но боты и коммерческие
проекты обычно лежат в приватных репозиториях заказчика. Такие работы
добавляются вручную в массив `PROJECTS` (`js/content.js`) — они показываются
выше списка репозиториев:

```js
{
  year: '2026',
  link: 'https://t.me/имя_бота',   // необязательно
  uk: { name: '…', desc: '…', tags: ['aiogram', 'PostgreSQL'] },
  en: { name: '…', desc: '…', tags: ['aiogram', 'PostgreSQL'] }
}
```

Репозитории, которые не нужно показывать (например, сам сайт), перечисляются
в `HIDDEN_REPOS`. Нулевые счётчики (0 звёзд, 0 подписчиков) скрываются сами.

Важно: у каждой услуги, шага и вопроса должны быть **оба** языка (`uk` и `en`),
иначе проверки не пропустят деплой.

## Языки

Украинский и английский. Сайт определяет язык по локали браузера: украинская
или русская локаль → украинский, всё остальное → английский. Выбор
пользователя запоминается в `localStorage`, переключатель UA/EN — в шапке.

## Проверки

```bash
node scripts/check.js
```

Проверяет пропущенные переводы, битые якоря, наличие CSP, `rel="noopener"`
на внешних ссылках, отсутствие `innerHTML` и вес страницы. Запускается в CI —
если что-то сломано, сайт не публикуется.

## Локальный запуск

```bash
python3 -m http.server 8000
# открыть http://localhost:8000
```

Открывать нужно исходники в корне: они читаемые, с комментариями и
без версий в путях. Собранная копия лежит в `dist/` и в репозиторий
не попадает.

## Сборка

```bash
npm ci
npm run build            # проверки + свои библиотеки + сборка → dist/
npm run build:offline    # только сборка, без сети — для локальной работы
```

`npm run build` — команда сборки для Cloudflare, и она же прогоняет
проверки. Локально без сети берите `build:offline`: тогда gsap и
lenis останутся на CDN, и это нормально для разработки.

`build.js` снимает комментарии, жмёт html, css и js (−33% текста),
проставляет версию своим файлам, чтобы браузер не держал в кеше
старый скрипт рядом со свежей разметкой, и выкидывает из публикации
всё лишнее: макеты для инстаграма (19 МБ), сами скрипты сборки и
readme. В CI оба шага выполняются перед публикацией, наружу едет
только `dist/`.

Если `vendor/` есть, сборка заменяет адреса gsap, ScrollTrigger и
lenis на локальные и ужимает CSP до `script-src 'self'`. Если нет —
остаются адреса CDN, и это нормально для локальной работы.

## Про исходники: чего сделать нельзя

**Спрятать фронтенд от посетителя невозможно.** Браузер обязан
получить html, css и js целиком, иначе ему нечего показывать.
Минификация снимает комментарии и укорачивает имена — читать
становится неприятно, но логика достаётся за полчаса. Обфускация
добавляет ещё пару часов работы тому, кому очень надо, а взамен
раздувает файл и ломается на ровном месте. Это замок на калитке,
а не стена.

Сейчас исходники и вовсе лежат открыто: репозиторий публичный,
потому что бесплатный GitHub Pages умеет публиковать только из
публичного репозитория. Пока это так, минификация не скрывает
ничего — рядом лежит оригинал с комментариями.

## Переезд на Cloudflare (закрывает исходники)

Цель — сделать репозиторий приватным. Бесплатный GitHub Pages из
приватного репозитория публиковать не умеет, Cloudflare — умеет.
Порядок важен: сначала поднимаем новую площадку, убеждаемся, что
она работает, и только потом закрываем репозиторий.

Cloudflare сейчас заводит такие проекты как **Workers со
статическими файлами** (не Pages). Разницы для нас почти нет:
`_headers` там работает так же, а что публиковать — сказано в
`wrangler.jsonc`.

**1. Подключить проект** (репозиторий пока публичный)

Dashboard → Workers & Pages → Create → импорт репозитория
`virtuaall1/site`. Настройки сборки:

| Поле | Значение |
| --- | --- |
| Build command | `npm run build` |
| Deploy command | `npx wrangler deploy` (по умолчанию) |
| Output / assets directory | задан в `wrangler.jsonc` — `./dist` |

Версия Node берётся из `.node-version` (22). Каталог публикации в
панели можно не трогать: `wrangler.jsonc` в репозитории главнее, и
именно он не даёт wrangler утащить в деплой весь `node_modules`.

Дождаться сборки и открыть выданный адрес — сайт должен работать
целиком, вместе с тремя кейсами.

**2. Прописать адрес.** Settings → Variables → `SITE_URL` =
выданный адрес со слешем на конце (или сразу свой домен). Пересобрать.
Это чинит `canonical`, `og:url`, `sitemap.xml`, `robots.txt` и
ссылки на кейсы: в исходниках они записаны как GitHub Pages, а
сборка подменяет адрес на этот.

**3. Закрыть репозиторий.** GitHub → Settings → General → Danger
Zone → Change visibility → Private. Cloudflare продолжит собирать:
доступ у него через GitHub App, а не через публичность.

**4. Старое убрано.** Workflow GitHub Actions удалён: он слал
уведомления о сборках, которые больше ни на что не влияли. Проверки
из него не потерялись — `npm run build` теперь сам прогоняет
`scripts/check.js` перед сборкой, и упавшая проверка роняет сборку в
Cloudflare, как раньше роняла деплой.

Что изменится после переезда:

- **Заголовки безопасности включатся сами** — `_headers` лежит
  внутри `dist` и разбирается Cloudflare. На GitHub Pages он лежал
  без дела.
- **Старый адрес `virtuaall1.github.io/site` больше не наш.** Он
  остался в профиле GitHub, в шапке инстаграма и напечатан на
  картинках в `brand/instagram/` — это надо поменять и перерендерить.
  Новый адрес — `vrtll.dev`, почта — `admin@vrtll.dev`.
- **Полоса языков не сломается.** Приватный репозиторий не отдаёт
  языки наружу, поэтому объём своего кода (сайт и три сайта из
  кейсов) считает сборка и подставляет в `content.js`. Остальные
  языки по-прежнему приходят из GitHub API — публичный профиль,
  число репозиториев и подписчиков тоже остаются на месте.

Что защищать всерьёз стоит — не разметку, а доступы: токены, ключи
и любые секреты на фронтенде не живут в принципе, их место на
сервере. На этом сайте их нет: единственные запросы наружу —
публичный GitHub API и курс НБУ, оба без ключей.

## Технические решения

- **Безопасность:** строгий CSP (`default-src 'none'`, в сборке — ещё и
  `script-src 'self'`), библиотеки анимации переносятся к себе на этапе
  сборки, так что сторонний домен не исполняет код у посетителя; данные из
  GitHub API попадают в DOM только через `textContent`; внешние ссылки с
  `noopener noreferrer`; заголовки безопасности готовы в `_headers`.
- **Скорость:** нет сборки и фреймворков в бандле; ответы GitHub API кэшируются
  в `sessionStorage` на 30 минут, чтобы не упираться в лимит 60 запросов/час;
  фоновая анимация останавливается на неактивной вкладке.
- **Анимации:** GSAP + ScrollTrigger и Lenis грузит сам `app.js` и только
  там, где анимации работают: на телефоне и при `prefers-reduced-motion`
  эти 150 КБ не скачиваются вовсе. Сайт полностью работает и без них —
  есть фоллбэк на IntersectionObserver.
- **Доступность:** skip-link, фокус-стили, `aria-expanded` на аккордеоне,
  полное отключение анимаций при `prefers-reduced-motion`.
